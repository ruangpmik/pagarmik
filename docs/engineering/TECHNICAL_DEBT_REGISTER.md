# Technical Debt Register

Estimates are preliminary relative sizes, not delivery commitments. Priority reflects current evidence and production impact.

| ID | Description / root cause | Impact and risk | Priority | Remediation | Complexity / dependencies | Status |
|---|---|---|---|---|---|---|
| TD-001 | Active data/auth paths use local JSON; Prisma adapter is not implemented | Data is not shared transactionally across instances; local files may be ephemeral | P1 | Design persistence boundaries; implement Prisma adapter and reviewed migrations; add transaction and restore tests | L | Open |
| TD-002 | Verification JSON has no cross-process locking or tamper protection | Concurrent writers can lose events; local actor can alter history | P1 | Move audit/status to a database transaction; restrict access and back up; test concurrency/restore | M-L; depends TD-001 | Open |
| TD-003 | Global middleware checks host equality only when Origin exists; it does not compare full origin and accepts missing Origin | CSRF policy is incomplete outside the verification route | P1 | Review supported clients and enforce an explicit full-origin/CSRF-token policy across all mutating routes | M; route compatibility review | Open |
| TD-004 | Login `next` validation accepts any path beginning `/`; auth endpoints lack rate limiting; registration cookie options differ from login | Open-redirect/phishing and brute-force/session hardening risk | P1 | Allowlist internal paths; add tested auth throttling; align secure cookie attributes | M | Open |
| TD-005 | Case analysis includes fixed risk/recommendation text not derived from retrieved evidence | Legal information may appear better sourced than it is | P1 | Ground sections in validated sources or label/remove unsupported sections; add no-source tests | M | Open |
| TD-006 | Lint script exists but ESLint package/config is absent | No reliable lint gate; current command may fail or prompt | P2 | Choose and configure a compatible linter deliberately, then add CI gate | S-M; dependency review | Open |
| TD-007 | Dependency/secret/license scanning and SBOM are not configured | Supply-chain and secret exposure checks are not evidenced | P2 | Select approved tooling and least-privilege workflow; record scanner results | M; repository owner policy | Open |
| TD-008 | Local tests, typecheck, lint, and build have not run because dependencies are absent | Current implementation has unverified compile/runtime behavior | P1 | Validate in CI or a reviewed lockfile-installed environment | S; needs dependency availability | Open |
| TD-009 | Git metadata absent from current folder | Cannot attribute local changes or review a diff | P2 | Obtain canonical clone/source checkout and reconcile files without overwriting | S; requires correct repository source | Open |
| TD-010 | Regulation detail embeds metadata in JSON-LD via `dangerouslySetInnerHTML` using raw `JSON.stringify` | Stored script-terminator content from an ingested regulation may execute in a viewer's browser | P1 | Use a JSON-LD serializer that escapes `<` (and test `</script>` input) | S; focused page regression test | Open |
| TD-011 | Docker Compose runs `prisma db push` on app startup | Startup performs schema mutation against the configured database without a reviewed migration/recovery gate | P1 | Replace with an explicit, reviewed migration/release step after production DB architecture is approved | M; production/database approval | Open |
| TD-012 | Docker build installs from `package.json` without copying the lockfile in the dependency stage | Image dependency resolution is not guaranteed to match the repository lockfile | P2 | Make the image build consume the committed lockfile via `npm ci`; verify container build in CI | S; Docker build validation | Open |
| TD-013 | Admin ingest accepts arbitrary PDF/text without assurance that personal/health data is excluded | Sensitive data could be stored in ignored local runtime files or included in retrieval | P1 | Define source/contents restrictions, add privacy review and retention/deletion controls; reject patient records in the product flow | M; product/legal owner input | Open |
| TD-014 | Configurable external AI provider sends question and retrieved context without evidenced data-flow consent/disclosure controls | Personal/health details could leave the deployment boundary | P1 | Document providers/data regions/retention, obtain product authorization and user disclosure, and enforce safe provider policy | M; provider and legal review | Open |
| TD-015 | Seeded regulation relationships have no per-edge article citation, source URL, or verification state | A relationship can be shown without auditable legal provenance, weakening trust in the graph | P1 | Extend the relation record with evidence and verification metadata; verify each edge against official text before presenting it as legally confirmed | L; legal-source review required | Open |
